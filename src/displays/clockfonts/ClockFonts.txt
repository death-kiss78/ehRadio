The DS_DIGI fonts marked as 56pt7b actual height: 70 pixels / width: 54 pixels (colon: 24) - non-mono 1 is 29px
                         ...42pt7b actual height: 52 pixels / width: 40 pixels (colon: 15) - non-mono 1 is 15px
                         ...28pt7b actual height: 35 pixels / width: 27 pixels (colon: 11) - non-mono 1 is 12px
                         ...15pt7b actual height: 19 pixels / width: 14 pixels (colon: 6) - non-mono 1 is 6px
So likely the point size relates to the true type font it was derived from (which may include below the baseline).

The link https://tchapi.github.io/Adafruit-GFX-Font-Customiser/ originally appeared in the comments for the font*.h files.
It is a font editor but not enjoyable to use.

Chunky6 is a Trip5 font designed for pixel displays: https://github.com/trip5/Matrix-Fonts

Let's generate a font from a PNG using my own tool to make the "0123456789:" graphic: https://trip5.github.io/Matrix-Fonts/renderer.html -
note that the PNG was edited using Windows Paint to make sure the characters were a bit center-right.
This tool can be used on ANY BDF font (a python script is also available in that repository).

Numbers are a fixed-width and the colon is half of that width - this including spaces.  The result is the total width will be divisible by 21.
Note that it adds a 1 or 2 pixel border all around and we then add black borders and trim
so that there are equal numbers of black pixels left-right and top-bottom, odd ones getting extra space on left and bottom...

Or more simply, every digit needs to fit into the following patterns (pixel sizes), with the colon being half of the width of a digit:
Size (height) x width: 70 x 56, 52 x 40, 35 x 28, 15 x 12.

Chunky6_70:    pixel size 14
Chunky6_70_px: pixel size 11 + 3 pixels space
       height: 5 * 14 = 70 pixels
        width: 4 (includes 1 empty column) * 14 = 56 pixels (per digit) x 10.5 = 588 pixels
- Time is longer than DS_DIGI56pt7b_mono by 12 pixels

Chunky6_52:    pixel size 10
Chunky6_52_px: pixel size 8 + 2 pixels space
       height: 5 * 10 = 50 + 1 blank top + 1 blank bottom = 52 pixels
        width: 4 (includes 1 empty column) * 10 = 40 pixels (per digit) x 10.5 = 420 pixels
- Time is longer than DS_DIGI42pt7b_mono by 5 pixels

Chunky6_35:    pixel size 7
Chunky6_35_px: pixel size 6 + 1 pixels space
       height: 5 * 7 = 35 pixels
        width: 4 (includes 1 empty column) * 7 = 28 pixels (per digit) x 10.5 = 294 pixels
- Time is longer than DS_DIGI28pt7b_mono by 7 pixels

Chunky6_15:    pixel size 3
Chunky6_15_px: pixel size 2 + 1 pixels space
       height: 5 * 3 = 15 pixels
        width: 4 (includes 1 empty column) * 3 = 12 pixels (per digit) x 10.5 = 126 pixels
- Time is shorter than DS_DIGI15pt7b_mono by 8 pixels

This is the tool that can converts the PNG to a .h font file:
py .\png_to_gfxfont.py Chunky6_70_px.png Chunky6_70_px.h --glow-char /

That glow-char switch makes the "glow" character (the residual "LED" behind the character).
No extra glyph is needed for that... the script will extrapolate the special character.
If no glow character is needed or desired, 
The DS_DIGI characters are 7-segment characters so they just the "8" character.

There is some risk that these slightly wider fonts may not fully fit on all displays...

After creating the font files, the /src/displays/clockfonts/font*.h files need to be edited to include them in builds.
